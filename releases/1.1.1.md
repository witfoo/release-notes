# WitFoo Analytics 1.1.1

## Summary

WitFoo Analytics 1.1.1 is a **maintenance release** covering everything since 1.1.0: appliance
reliability fixes, broader VMware and Azure data-onboarding coverage, reporter and demo-data
corrections, the new **WitFoo Console** deployment option, and a security pass that closes a
report-access permission gap and updates a networking dependency. It is a recommended, drop-in
upgrade for all 1.1.0 deployments — there are no breaking changes and no manual migration steps.

Alongside it, **WitFoo Agent (WFA) 2.4.13** ships the appliance-side fix at the centre of this
release, and consolidates every agent hotfix published since 2.4.8 into one build.

## What's New

### Appliance reliability

- **Changing a node's role no longer leaves the old stack behind.** Reconfiguring an appliance from
  one role to another (for example Conductor → All-in-One) previously left the previous role's
  containers running and holding their network ports, so the new role's web front end could not
  start — the appliance came up incomplete with a "port is already allocated" error repeating in the
  agent log. The agent now reclaims the previous role's containers before starting the new ones, and
  again on its regular reconcile pass, so a role change completes cleanly. Only WitFoo's own
  containers are ever reclaimed; anything else running on the host is left untouched.
  *(Requires WFA 2.4.13.)*
- **A single stubborn container no longer blocks the rest of a shutdown.** Stopping the agent now
  attempts every container and reports all failures together, instead of abandoning the remainder at
  the first problem — which was one of the ways a stale stack was left behind in the first place.
- **Cleaner upgrades and disk reclamation.** Unused container images and orphaned message-broker data
  left by earlier upgrades or re-identification are now reclaimed automatically.
- **Support packages are complete and safe to share.** Diagnostic bundles now capture the Conductor
  UI and both message brokers, and no longer include configuration secrets.
- **All-in-One + Conductor appliances now report pipeline health.** These appliances previously
  emitted no pipeline metrics in their status reports, leaving connector and pipeline health
  invisible for that role.
- **Capacity enforcement is reported truthfully while the measurement basis is corrected.** Disk
  capacity alerts continue to fire, but enforcement no longer escalates past a warning during this
  release, so an appliance cannot be blocked from ingesting because of a measurement change.
- **Password reset on the appliance repairs older installs.** The `wfa user-reset` command now heals
  a schema difference that could otherwise cause it to fail.

### Data onboarding — broader coverage

- **VMware and Dell VxRail coverage widened.** Additional ESXi, vCenter, NSX, vSAN and VxRail log
  formats are now recognized and classified, from real unrecognized-traffic analysis of live fleets.
- **New device coverage** for Arista flow control, Stealthbits Activity Monitor, and CalPrivate.
- **Corrected stream and event classifications** for the 2026-08 device batch, so those events land
  in the right places in investigations and reports.
- **Azure and Microsoft connector resilience.** Microsoft Sentinel, Microsoft Graph, Defender for
  Vulnerability Management and LimaCharlie connectors now handle authentication token responses
  robustly, ending a class of intermittent collection failures.
- **Log framing corruption fixed.** A framing defect could corrupt events arriving over
  newline-delimited TCP; those events are now delivered intact. Corrupted byte-window framing is
  now classified as a transport problem rather than treated as an unknown device type.

### Deployment

- **WitFoo Console deployment option.** Console can now be selected as a node role during appliance
  configuration and licensed as its own no-cost option, for remote management and monitoring of a
  fleet.

### Reporter

- **Reporter no longer returns errors or empty pages on long report operations.** Report generation
  and date-range queries are exempt from the short request timeout that had been cutting them off,
  and report generation is now restricted to administrators.
- **Demo cost-savings report no longer shows all zeros.**

## Security

1.1.1 includes a focused security pass. Consistent with our practice, we describe what changed
without publishing exploitation detail.

- **Report access now enforces role permissions.** The reporting endpoints validated that a caller
  was authenticated and belonged to the organization, but did not check the caller's *role* — so any
  signed-in member of an organization could read report snapshots and export them to CSV, including
  roles intended to have no reporting access at all. Every reporting route now enforces the
  appropriate read or export permission, and an automated check prevents the gap from recurring.
  **Upgrade recommended.** No cross-organization exposure was possible at any point — organization
  scoping was always enforced.
- **Networking dependency updated.** The gRPC library used for internal service communication was
  updated to its patched release (a high-severity advisory affecting the previous version).
- **Security alert review completed.** Every open code-scanning finding for this release was
  reviewed and either fixed or documented with a specific justification, with residual items
  recorded and owned rather than left untriaged. One accepted-risk item — a default session signing
  key used only when an installation does not set its own — was documented and scheduled for a
  dedicated fix; operators who set `SECRET_KEY` on Console deployments are unaffected.
- **Supply-chain hardening.** The container-image build no longer fetches a command-line tool over
  the network during the build, removing a fetch-and-execute step from the build path.

### Monitoring and delivery pipeline

- Fleet-outage detection no longer depends on the telemetry that an outage suppresses, alert
  thresholds now count unbroken failure streaks rather than counts in a window, and probes blocked by
  an intermediary are reported as unverified instead of healthy.
- Approved device parsers now propagate to customer-production images automatically.

## Upgrade Notes

- **No breaking changes.** 1.1.1 is a drop-in upgrade from 1.1.0.
- **Update WFA to 2.4.13** to get the role-change and support-package fixes; appliances with
  automatic updates enabled pick it up on their next check.
- No manual database migration is required — schema changes self-heal on start.
- **Role-permission change to be aware of:** report reads now require a reporting read permission and
  CSV export requires the export permission. Roles that were intended to have reporting access
  already hold these; any custom role that relied on the previous unchecked behavior must be granted
  the appropriate permission.
- Enforcement of disk-capacity limits is clamped to warnings in this release while the underlying
  measurement is corrected; alerts still fire normally.

| Verification | Scope | Result |

**Testing & validation.** Every change in 1.1.1 was verified by automated gates on the release
branch: the aggregated CI suite, the offline air-gapped build contract, and the permission and
route-authorization guards that pin the reporting-access fix. Each behavioral fix in this release
ships with a regression test that fails if the fix is reverted. Live appliance validation was not
performed for this maintenance release; deployments that require lab verification before rollout
should stage 1.1.1 in a non-production environment first.
